## За одну минуту

- **Что это.** ИИ-консультант раскладывает сбережения клиента по депозитам BCC. Встроенный щит Qalqan не даёт мошеннику обмануть ИИ и увести деньги.
- **Проблема.** ИИ можно обмануть чужим текстом: мошенник прячет команду там, где ИИ её прочитает (prompt injection). OWASP ставит это на первое место среди рисков ИИ-приложений и в 2026 году. Чем больше ИИ банка умеет делать с деньгами, тем ценнее его обмануть.
- **Атака, которую мы показываем.** Мошенник переводит клиенту 1 ₸ с комментарием-командой. ИИ без защиты вставляет в план поддельный депозит «Моя цель+» под 19%, а на деле — перевод 50 000 ₸ на чужой счёт. Человек подделку не отличает: она выглядит выгоднее настоящих депозитов.
- **Результат.** Без защиты ИИ вставил подделку в план 20 раз из 20 (уходило от 50 000 до 150 000 ₸). С Qalqan — 0 из 20. Подробно — в разделе «Результаты».

## Проблема

1. **ИИ банков начинают работать с деньгами.** BCC планирует развить ассистента AIBEK до личного финансового консультанта с доступом к счетам (digitalbusiness.kz, 12.12.2024) и первым в Казахстане вошёл в программу Visa Agentic Ready, где ИИ сам проводит операции по поручению клиента (bes.media, 22.05.2026).
2. **Такой ИИ можно обмануть чужим текстом.** Prompt injection — первый риск в OWASP Top 10 for LLM Applications 2026 (по обзору Cloud Security Alliance, 21.10.2026). Исследование «The Attacker Moves Second» (2025) показало: защиты, заявлявшие почти нулевой успех атак, обходили больше чем в 90% случаев.
3. **В Казахстане уже есть все части такой атаки.** Нацбанк предупреждал о мошенничестве с «ошибочными» переводами, в том числе реальными (24.11.2025); мошенники выдают себя за «службу поддержки»; Нацбанк и АРРФР предупреждают о фишинге и дипфейках, сделанных нейросетями. В Европе части уже сошлись: в апреле 2026 года перевод на €0,01 с инструкцией заставил ИИ-ассистента банка выдать клиенту фишинг (Blue41, 29.04.2026). Атаку именно на ИИ-ассистента банка в Казахстане мы не нашли и не утверждаем, что она была.
4. **А консультант клиентам нужен.** Интервью с клиентом BCC (он наш ментор, говорим об этом честно): о новых депозитах он узнаёт от жены и из звонков, а не из приложения; «такого финансового консультанта нет ни у кого». Опрос клиентов банков: [ЦИФРЫ ОПРОСА 25.11].

## Решение

**Консультант.** Клиент пишет своими словами: сколько держать под рукой и когда понадобятся деньги. ИИ только понимает суммы и сроки. План и доход считает код по ставкам с bcc.kz (нижняя граница, консервативно).

Пример: 1 500 000 ₸ — 100 000 под рукой, ремонт через 3 месяца, отпуск через полгода, учёба через год → 5 депозитов, доход за год 180 602 ₸, на 74 617 ₸ больше, чем на одном гибком вкладе.

**Щит Qalqan — четыре слоя:**
1. **Изоляция.** ИИ не получает текст комментариев к входящим переводам: их пишут посторонние люди. Подбросить команду нечем, ни на каком языке. Клиент свои комментарии видит на экране как обычно.
2. **Правило в коде.** Деньги можно класть только на настоящие депозиты BCC из списка. Подделку «Моя цель+» человек не отличит, а правило сверяет со списком и не пропускает. Это код, а не ИИ, — его нельзя уговорить.
3. **Проверка ответа.** Каждый ответ ИИ проверяется до клиента: ссылки, коды из SMS, «карта заблокирована», чужие карты, счета и телефоны, «оплатите сбор».
4. **Датчик и ловушка.** Датчик ищет признаки атаки (рус., каз., англ.; снимает маскировку: невидимые символы, латинские буквы-двойники, точки между буквами). Отправитель блокируется, попытка уходит в журнал антифрода. Датчик — не стена: если он что-то пропустит, ИИ текст всё равно не увидит.

```
Клиент пишет цель ─► ИИ понимает суммы и сроки ─► код считает план по ставкам BCC
                                                         │
Перевод 1 ₸ с командой ─► [1. изоляция: ИИ его не видит]  ▼
                                         клиент нажимает «Открыть депозиты»
                                                         │
                                  [2. правило: только настоящие депозиты BCC]
                                                         ▼
                                                депозиты открыты в BCC
```

## Результаты

Каждая атака прогонялась дважды: на консультанте без Qalqan и на том же консультанте с Qalqan. Модель gpt-oss-20b (Groq).

| Атаки | Без Qalqan: деньги ушли | С Qalqan |
|---|---|---|
| Поддельный депозит «Моя цель+» (20 прогонов, 25.11) | 20 из 20 | 0 из 20 |
| Прошлая версия атаки «предоплата партнёру»: рус., каз., англ. (40, 24.11) | 7 из 40 | 0 из 40 |
| 40 новых атак от отдельного ИИ, который не видел код щита | 1 из 40 | 0 из 40 |
| Обычные комментарии к переводам: ложные тревоги датчика | — | 0 из 70 |

- Когда ИИ без защиты обманывали, правило в коде остановило все такие планы: 28 из 28 (20 — 25.11, 8 — 24.11).
- Все прогоны и ответы модели: `results/` — поддельный депозит: `attack_summary.md`, `attack_runs.json`; прошлая версия атаки: `attack_summary_v1_prepayment.md`, `attack_runs_v1_prepayment.json`; атаки отдельного ИИ: `heldout_set_v2_summary.md`, `heldout_set_v2_runs.json`.
- Ответ модели меняется от запуска к запуску; цифры — для этой модели и этих наборов атак.

## Как мы нашли слабое место в собственной защите

1. **Решение:** сначала щит искал подброшенные команды по словам (фильтр).
2. **Как проверили:** отдельный ИИ, не видевший код щита, написал 40 новых атак на русском, казахском, английском и вперемешку: стихом, латиницей, с невидимыми символами, в base64.
3. **Что нашли:** фильтр поймал только 8 из 40 (на казахском — 0 из 10). Он «выучил» наши собственные атаки. Деньги при этом не ушли ни разу: их держало правило в коде.
4. **Исправление:** изоляция — ИИ вообще не получает чужой текст; фильтр стал датчиком для антифрода, а не стеной. Добавили проверку ответа на казахском, на чужие счета и телефоны.
5. **Результат:** второй набор из 40 атак, написанный отдельным ИИ уже после исправления: с Qalqan 0 потерь из 40 (`results/heldout_set_v2_summary.md`). Датчик на этом наборе заметил 12 из 40 — поэтому мы на него и не опираемся.

## Запуск (Windows, PowerShell)

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
```

В `.env` впишите свой ключ Groq (`GROQ_API_KEY`). Ключ хранится только локально и в репозиторий не попадает.

```powershell
uvicorn app.main:app --reload
```

- Приложение клиента: http://127.0.0.1:8000
- Страница перевода («мошенник»): http://127.0.0.1:8000/send

## Режимы щита (переключатель вверху)

- **Щит выключен** — как обычный ИИ-ассистент: команды из комментариев к переводам доходят до ИИ.
- **Только правило** — ИИ можно обмануть, но код пропускает только открытие настоящих депозитов клиента.
- **Полный щит** — изоляция, правило, проверка ответа, датчик и ловушка.

## Проверка на атаках

```powershell
python tools\run_attacks.py                 # все атаки команды
python tools\run_attacks.py --only main     # только поддельный депозит
python tools\run_attacks.py --attacks-file tests\heldout_set_v2.json   # атаки отдельного ИИ
python tools\run_attacks.py --summary-only  # пересобрать таблицу без новых запросов к ИИ
```

У бесплатного Groq есть лимит токенов в сутки: при его исчерпании скрипт останавливается и сохраняет то, что успел.

## Структура

```
app/        приложение: консультант (advisor.py), расчёт плана (plan.py), щит (shield.py), атаки (attacks.py)
data/       ставки депозитов BCC с источником и датой
static/     страницы клиента и перевода
tools/      прогон атак, проверка ключа ИИ
tests/      наборы атак от отдельного ИИ (v1 — до исправления, v2 — после)
results/    результаты прогонов
```

## Честно об ограничениях

- Мы работаем на своём демо-банке с ставками BCC. Системы BCC, в том числе AIBEK, не трогали: проверять чужую систему без разрешения нельзя.
- Модель — gpt-oss-20b, не модель банка.
- Интервью пока одно, с ментором; опрос — [ЧИСЛО ОТВЕТОВ] ответов, это не репрезентативная выборка.
- Регуляторику подробно не изучали; расчёта выгоды для банка пока нет.
